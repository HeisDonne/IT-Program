# Tables

## Placeholders used
`table_name`, `column1`, `column2`, etc. represent your actual table and column names — chosen by you when designing a schema, not generated by any command. `id` is left as-is since it's the near-universal convention for a primary key column.

## Definition
A table is a structured collection of rows, where every row has the same fixed set of typed columns. The table name is typically the plural of what's being stored (`products`, `employees`); each column represents one attribute every row must have a value (or `NULL`) for.

## CREATE TABLE

```sql
CREATE TABLE table_name (
    id SERIAL PRIMARY KEY,
    column1 VARCHAR(100) NOT NULL,
    column2 VARCHAR(255) UNIQUE NOT NULL,
    column3 NUMERIC(10, 2),
    column4 TIMESTAMP DEFAULT NOW()
);
```

What each part contains:
- `CREATE TABLE table_name` — the statement keyword and the name of the new table.
- `( ... )` — the column list, one definition per line, each in the form `column_name DATA_TYPE constraints`, separated by commas (no trailing comma after the last one).
- `id SERIAL PRIMARY KEY` — `SERIAL` creates an auto-incrementing integer, backed by a hidden sequence Postgres manages; `PRIMARY KEY` marks it as the row's unique identifier. (`GENERATED ALWAYS AS IDENTITY` is the modern standards-aligned equivalent of `SERIAL`.)
- `;` — terminates the statement.

## Data types

| Type | Holds | Notes |
|---|---|---|
| `INTEGER` / `SERIAL` | Whole numbers | `SERIAL` = auto-incrementing `INTEGER` |
| `VARCHAR(n)` | Text capped at `n` characters | `n` is a hard limit — inserting longer text errors |
| `TEXT` | Text, no length limit | |
| `NUMERIC(p, s)` | Exact decimal numbers | `p` = total digits, `s` = digits after the decimal point; use for money, not floating-point types |
| `BOOLEAN` | true/false | |
| `DATE` | Calendar date, no time | |
| `TIMESTAMP` / `TIMESTAMPTZ` | Date + time | `TZ` variant also stores timezone offset |
| `UUID` | Unique identifier string | Alternative to `SERIAL` for primary keys |
| `JSONB` | Structured JSON | Stored in binary form, indexable and queryable |

## Constraints

| Constraint | Contains | Effect |
|---|---|---|
| `PRIMARY KEY` | — | Uniquely identifies each row; implies `NOT NULL` + `UNIQUE`; one per table |
| `NOT NULL` | — | Rejects inserts/updates leaving the column empty |
| `UNIQUE` | — | Rejects a value that already exists elsewhere in the column |
| `DEFAULT value` | The fallback value | Used when an insert doesn't specify this column |
| `CHECK (condition)` | A boolean expression | Rejects any row where the expression evaluates false, e.g. `CHECK (column3 >= 0)` |
| `FOREIGN KEY` / `REFERENCES` | Another table + column | Value must match a primary key value in that table (see **Relationships**) |

## ALTER TABLE

```sql
ALTER TABLE table_name ADD COLUMN new_column BOOLEAN DEFAULT true;
```
- `ADD COLUMN new_column BOOLEAN DEFAULT true` — adds a new column, back-filling every existing row with `true` since they had no prior value.

```sql
ALTER TABLE table_name ALTER COLUMN column1 TYPE TEXT;
```
- `ALTER COLUMN column1 TYPE TEXT` — changes the column's data type; Postgres attempts to convert existing values and fails the whole statement if any value can't convert.

```sql
ALTER TABLE table_name RENAME COLUMN column1 TO renamed_column;
```
- Renames a column without affecting its data or type.

```sql
ALTER TABLE table_name DROP COLUMN renamed_column;
```
- Permanently removes the column and all data stored in it.

```sql
ALTER TABLE table_name ALTER COLUMN column2 SET NOT NULL;
ALTER TABLE table_name ALTER COLUMN column2 DROP NOT NULL;
```
- `SET NOT NULL` / `DROP NOT NULL` — adds or removes the constraint requiring a value in that column.

## DROP TABLE

```sql
DROP TABLE table_name;
```
- Permanently deletes the table and every row in it. Errors if the table doesn't exist.

```sql
DROP TABLE IF EXISTS table_name;
```
- `IF EXISTS` — suppresses the error if the table isn't there, making the command safe to re-run.

## Indexes

```sql
CREATE INDEX idx_table_name_column1 ON table_name(column1);
```
- `idx_table_name_column1` — the index's own name (convention: `idx_<table>_<column>`).
- `ON table_name(column1)` — the table and column the index is built on.

Speeds up lookups/sorts filtered on `column1`, at the cost of extra disk space and marginally slower writes to that column. `PRIMARY KEY` and `UNIQUE` columns are indexed automatically.

## Inspecting tables (psql meta-commands)

```
\dt              -- list every table in the current database
\d table_name    -- show table_name's columns, types, and constraints
\d+ table_name   -- same, plus extra detail (e.g. on-disk size)
```
These start with `\` and are specific to the `psql` client — not valid inside application code.
